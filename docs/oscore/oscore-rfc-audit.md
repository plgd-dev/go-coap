# RFC 8613 implementation audit

This is a source-and-test audit of the supported pre-established unicast
OSCORE implementation. It is not a conformance certificate. An implemented
row indicates source and focused test evidence, not exhaustive fault, timing,
or deployment validation. The proxy implementation is a minimal one-request/
one-response forwarder, not a complete implementation of every RFC 8613 proxy
operation.

Status meanings:

- **Implemented**: supported path has source and related test evidence.
- **Partial/gap**: behavior is incomplete or differs from a requirement within
  the advertised scope.
- **Unverified**: focused evidence is insufficient; this is not a claim that the
  requirement is met.
- **Outside scope**: the capability is not advertised by this implementation.

## Requirements and evidence

| RFC section / requirement | Status | Implementation and test evidence / qualification |
|---|---|---|
| 2: encode/decode the OSCORE option, including KID, Partial IV, and ID Context fields. | Implemented | [Option codec](../../net/oscore/option.go), [RFC encoding vectors and malformed-input tests](../../net/oscore/option_test.go). |
| 4.1: form inner/outer messages and apply E, I, and U option processing for OSCORE endpoints. | Implemented for the supported client/server roles | [Message split and AAD](../../net/oscore/message.go), [option-class tests](../../net/oscore/message_test.go), and [request/response round-trip tests](../../net/oscore/protect_test.go). Class U options are kept outside the ciphertext and restored at the receiving endpoint; Class E and unknown options are protected. The RFC currently defines no Class I options. Proxy forwarding semantics are a separate role and are not implemented. |
| 3: derive the supported security-context keys and common IV. | Implemented for supported suites | [Context derivation](../../net/oscore/context.go) implements HKDF-SHA-256 and AES-CCM-16-64-128, AES-CCM-16-64-256, AES-CCM-16-128-128, and AES-CCM-16-128-256; [Appendix C.1-C.3 vectors](../../net/oscore/context_test.go) and [suite selection/round-trip tests](../../net/oscore/context_test.go). The zero-value algorithm remains RFC 8613's default suite. Context establishment remains outside scope. |
| 5.2, 5.4: construct nonce and external AAD for protected messages. | Implemented | [Protection code](../../net/oscore/protect.go), [Appendix C.2/C.4 tests](../../net/oscore/context_test.go), [external AAD vectors](../../net/oscore/message_test.go). |
| 8: protect requests and responses, bind responses to the matching request, and reject failed authentication. | Implemented for supported message forms | [Request/response protection](../../net/oscore/protect.go), [Appendix C.4-C.8 vectors and malformed/tamper tests](../../net/oscore/protect_test.go), [context and policy tests](../../net/oscore/processor_test.go). Core malformed-message coverage includes invalid outer codes/options, duplicate OSCORE options, invalid response KID, and tampered ciphertext; it is not an exhaustive transport-specific malformed-datagram matrix. |
| 8: apply plaintext policy and avoid downgrade after OSCORE processing errors. | Implemented | [Processor policy](../../net/oscore/processor.go), [strict/mixed policy and no-fallback tests](../../net/oscore/processor_test.go). |
| 7.2, 7.4: sequence-number allocation, replay protection, and exhaustion. | Implemented; interface and file-backed persistence available | [Replay window](../../net/oscore/replay.go), [concurrent replay and persistence-failure tests](../../net/oscore/replay_test.go), [sequence allocation, oversized plaintext, and exhaustion tests](../../net/oscore/context_test.go), [file stores](../../net/oscore/store/file.go), and [file-store concurrency/restart tests](../../net/oscore/store/file_test.go). A `ReplayWindowStore` persists authenticated-window advances before requests are accepted; the file store locks Unix file operations and rejects stale/conflicting updates. |
| 7.5: behavior when part of the security-context state is lost, including receiver replay state after reboot. | Implemented with application-provided replay persistence | Configure `ReplayWindowStore` to load state on context creation and save authenticated advances before accepting messages. The `net/oscore/store` file implementation persists this state. Without a durable store, replay state remains in-memory and a restart loses it. |
| 4.1, 8: Observe registration, cancellation, and protected notifications. | Implemented in loopback tests on UDP/DTLS/TCP/TLS; external interop incomplete | [UDP](../../udp/oscore_test.go), [DTLS](../../dtls/oscore_test.go), and [TCP/TLS](../../tcp/oscore_test.go) cover registration, notifications, and cancellation; [libcoap interop](../../udp/client/libcoap_oscore_test.go) covers UDP. Independent DTLS/TLS Observe interoperability is not verified. |
| 7.3-7.4, 8: fresh Partial IVs and anti-replay checks for Observe notifications. | Implemented in tested paths | [Observe core tests](../../net/oscore/protect_test.go), UDP notification ordering, transport notification flows, and [bidirectional libcoap notification tests](../../udp/client/libcoap_oscore_test.go). |
| 4-8: classic Block1/Block2 with OSCORE. | Implemented for tested UDP/TCP paths; DTLS/TLS interop unverified | [UDP blockwise test](../../udp/oscore_test.go), [TCP blockwise test](../../tcp/oscore_test.go), and [libcoap blockwise test](../../udp/client/libcoap_oscore_test.go). |
| No-Response (RFC 7967) with protected requests. | Implemented for tested transports | [UDP](../../udp/oscore_test.go), [DTLS](../../dtls/oscore_test.go), and [TCP/TLS](../../tcp/oscore_test.go) verify that strict OSCORE policy does not dispatch plaintext requests, protected requests reach the handler, and suppressed responses are not sent. |
| 4.1.3.3, 10: decompose Proxy-Uri for OSCORE and forward an opaque protected request. | Partial | [Proxy-Uri decomposition](../../net/oscore/proxy_uri.go) keeps scheme/authority outside and protects path/query; [minimal forwarder](../../net/oscore/proxy/forwarder.go) enforces an application allowlist, strips proxy routing options, and preserves ciphertext and OSCORE option. [Forwarding round-trip test](../../net/oscore/proxy/forwarder_test.go) verifies the origin can decrypt and answer. This is a one-request/one-response path only; caching, Observe, blockwise proxy sessions, proxy authentication, and HTTP translation are not implemented. |
| 4-8: Q-Block, multicast, and group OSCORE combinations. | Partial / outside scope | UDP and DTLS Q-Block1 uploads and Q-Block2 downloads are tested with OSCORE; UDP is also tested against pinned libcoap. RFC 9177 defines Q-Block for datagram transports, so TCP/TLS use reliable-transport Blockwise rather than Q-Block. The pinned libcoap server's multi-block Q-Block2 echo response does not interoperate: at least one response lacks OSCORE protection, so go-coap rejects it. Group OSCORE and multicast OSCORE are specified separately and remain unsupported. |
| UDP/DTLS/TCP/TLS integration and mixed plaintext operation. | Implemented for tested flows; negative-case coverage incomplete | [UDP](../../udp/oscore_test.go), [DTLS](../../dtls/oscore_test.go), and [TCP/TLS](../../tcp/oscore_test.go) contain loopback coverage; mixed protected/plaintext acceptance, strict plaintext rejection, Observe, and No-Response are tested across the transports. Focused malformed-request tests on every transport reject a truncated OSCORE option, duplicate OSCORE options, an invalid outer request code, and an exposed Class E option before application dispatch. Response-side malformed transport cases and exhaustive malformed-datagram/fuzz coverage remain incomplete; core response validation is tested in [protect_test.go](../../net/oscore/protect_test.go). |
| Interoperability with an independent implementation. | Implemented for pinned libcoap UDP; CI execution is a release gate | [libcoap tests](../../udp/client/libcoap_oscore_test.go) exercise both client/server directions, Observe notifications, invalid contexts, tampering, and replay. The required job is defined in [test.yml](../../.github/workflows/test.yml). The OSS scanner image locally passed the full test suite with Q-Block and OSCORE required; remote CI execution must still be confirmed. |

The threat assumptions and additional security test guidance are maintained in
the repository [threat model](../../.oss-scanner/threat_model.md).
