## Reviewed implementation decisions

1. Q option bit encoding is independent because the existing classic codec rejects part of the 20-bit NUM range. Classic behavior is unchanged.
2. Decoder performs a second pass only for Q-bearing packets, preserving malformed classic options and Request-Tag as well. Mixed-option validation takes precedence over malformed individual values.
3. Unsupported Q responses are silently dropped rather than dispatched or answered with a request-style error.
4. Only CON rejection ACKs enter the existing response cache; fresh-MID NON errors are not cached under unrelated request keys.
5. Body size bounds payload bytes. The manager owns active-body reservations, identity/token budgets, and expiry; adapter-owned wire messages remain outside its accounting.

## Private UDP client Q1 upload and Q2 response milestone (2026-09-21)

The private `udp/client` adapter now sends eligible POST/PUT bodies as NON Q-Block1 bursts and receives Q-Block2 bodies for GET and upload responses. Q1 packets preserve the request method and copied request options, carry an owned Request-Tag, and use collision-checked connection token reservations plus fresh MIDs. Q1 Continue/missing/terminal controls route through all owned upload tokens and MIDs.

A valid first Q-Block2 response to a Q1 upload is validated before the sender ends, then handed to a receiver without replaying the request or consuming a second transfer slot. The handoff releases obsolete Q1 token/MID indexes. Subsequent Q2 Continue and repair requests preserve the initiating POST/PUT method and safe options, remove response-only/blockwise options and payload, and allocate fresh token/MID pairs. Control-token allocation stops after 32 unsuccessful candidates.

Start, handoff, encoding, allocation, and write failures roll back manager records, retained-byte/token accounting, adapter transfer/token/MID indexes, Q-Block token reservations, retained messages, and the original request handler. Completion, Tick expiry, caller abandonment, and session close use the same idempotent release path and report the original failure callback once. A channel-synchronized fake-session regression queues Tick, abandonment, and close against one live exchange and verifies exact-once failure, no deadlock or panic, and no residual private state. Existing Q2 control-write and 32-attempt token-exhaustion regressions now assert the same full cleanup and failure-once properties.

This is still private UDP client wiring. There is no public opt-in API, generic UDP support claim, server support, DTLS behavior claim, classic fallback change, Observe or multicast support, or interoperability claim.

## Private bidirectional UDP adapter completion (2026-09-22)

The private `udp/client` coordinator now exercises both Q-Block roles on one
connection-scoped manager. Its private server role admits and reassembles NON
Q-Block1 POST/PUT uploads, dispatches one copied request to the configured
handler, retains a Q-Block2 response for valid Continue/repair controls, and
keeps bounded duplicate-suppression records after response-write failure.

Q-Block2 controls are matched by the complete canonical request identity, not
by control token or ETag. Fresh control tokens are claimed transactionally;
malformed, conflicting, stale, wrong-SZX, wrong-identity, cross-owner, and
over-budget controls leave operation, manager-token, connection-token, and
retained-byte state unchanged. Direct repair output retains its accepted reply
token even when a later control arrives first; timer-generated output uses the
most recently accepted valid context.

Server-owned response MIDs remain routable for Reset until termination. Close,
write failure, Reset, expiry, and late handler return use generation-safe
cleanup: active state, MIDs, token reservations, manager budgets, records, and
metadata are released exactly once. Terminal duplicate-suppression records
consume their configured capacity only through their bounded retention time.

Same-package paired fake-session traces run both private-enabled roles without
sockets. POST and PUT traces cover a multi-set upload, duplicate final Q1 with
a new MID, a dropped Q2 fragment, recovery control/repair, complete assembled
client response, Request-Tag preservation, response-token/MID ownership, and
close cleanup.
