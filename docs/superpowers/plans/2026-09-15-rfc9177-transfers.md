# RFC 9177 Transfer Machines Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or superpowers:subagent-driven-development for the independent bounded tasks. Test each transition before implementation.

**Goal:** Implement deterministic per-body send/receive state machines, then integrate them under a bounded operation manager.

**Architecture:** Part A owns one already-identified body and emits owned actions. Part B validates wire metadata, correlates tokens, applies peer-wide probing budgets, and manages completed operations. The UDP adapter remains milestone 3. Part A alone is not network-ready RFC support.

**Tech Stack:** Go, existing qblock Body/Block helpers, explicit time.Time events, no sockets or new dependencies.

**Spec:** [Design](../specs/2026-09-15-rfc9177-design.md).

## Constraints and normalized contracts

- Preserve classic behavior and disabled-mode UDP gate.
- All Part A data describes one validated operation; the future manager authenticates control-token ownership before calling Continue/Repair/Finish.
- No wall clock, goroutine, or callback in Part A. Construction receives a jitter fraction in [0,1], sampled externally once per body.
- Copy retained input and emitted payloads. No pooled messages.
- Send actions advance the logical state. Adapter executes a returned burst in order before processing another event; any write failure calls Cancel and discards unsent actions. This explicit failure contract prevents replay.
- `Lifetime` is an absolute local resource limit. It is separate from protocol idle-recovery timeouts; duplicates never extend it. Parent operation context can impose an earlier deadline.
- Q1 means upload direction; Q2 means download direction. Receiver completion emits Deliver once. Q1 receiver remains available for duplicate-block notices until close/expiry; the manager supplies the retained application result. Q2 receiver emits Release immediately after Deliver.
- Sender Q1 awaits terminal application outcome after all initial blocks. Sender Q2 emits Complete after initial transmission, retains a bounded repair copy until Lifetime, and releases silently at expiry.

## Part A files and interfaces

- `transfer.go`: Kind, ActionKind, Action, TransferConfig, configuration validation, shared terminal errors.
- `timing.go`, `timing_test.go`: one jitter sample, fixed boundaries, saturating recovery backoff.
- `sender.go`, `sender_test.go`: initial sets, repair queue, matched continuation, terminal outcome, lifetime.
- `receiver.go`, `receiver_test.go`: sparse body, gap detection, continuation, retry timeout, single delivery, duplicates.
- `transfer_test.go`: synthetic end-to-end loss/reorder trace using emitted actions.

```go
 SendBlock ActionKind = iota + 1

func (s *Sender) Finish(err error) []Action
func (s *Sender) Cancel(err error) []Action

func NewReceiver(kind Kind, cfg TransferConfig, meta Metadata,
 now time.Time) (*Receiver, error)

 now time.Time) ([]Action, error)

```

Action semantics: SendBlock has a copied payload and Block. SendContinue.Through is the highest contiguous received block at a full-set boundary (manager encodes Q1 Continue or Q2 NUM=Through+1/M=true). RequestMissing.Numbers is ascending and bounded by MaxPayloads. Deliver.Payload is a new assembled body. Duplicate.Block identifies a received upload duplicate for the manager's response replay. Complete.Err describes sender outcome or receiver failure. Release tells the manager to release owned body state; it is emitted once.

## Task A1: timing/config contracts

Defaults: MaxPayloads=10, MaxBodySize=1 MiB, NonTimeout=2s, NonReceiveTimeout=4s, NonMaxRetransmit=4, Lifetime=247s. Reject zero limits, MaxPayloads>2^20, unsupported Kind in constructors, negative/nonpositive durations, retry counts>30, and receive timeout less than 1.5*NonTimeout+1s. Check duration overflow before arithmetic. Retry delay attempt 0 is NonReceiveTimeout; each subsequent attempt doubles, saturating at Lifetime. Send delay is NonTimeout*(1+jitter/2), fixed per sender; reject NaN/Inf/out-of-range jitter.

## Task A2: sender transitions

| State/event | Action/state change |
| --- | --- |
| New + Start | Send first fixed set; next send at now+sampled delay |
| Active + Tick before next send | None |
| Active + Tick at deadline | Send one queued repair set, else one initial set |
| Active + matching unused Continue | Advance next initial set immediately; only current set's last index matches |
| Active + stale/future Continue | Ignore |
| Active/retained + valid Repair | Validate all indices first; queue sorted unique blocks already initially sent; send first repair set immediately if no repair is already scheduled |
| Repair spanning boundaries | One set now, later set after sampled delay; resume initial sending after another delay |
| Q1 all initial sent | Await terminal Finish or Lifetime; repair still works |
| Q2 all initial sent | Emit Complete once; retain repair source until Lifetime |
| Finish/Cancel | Drop payload/queues; emit Complete if not already notified, then Release once |
| Lifetime expiry | Q1 Complete(ErrExpired)+Release; Q2 already complete gets Release only |

- [ ] Test Repair [8,12] after 0..19 were sent produces 8 now and 12 after delay; invalid/unsent/duplicate/descending/oversized reports error atomically with no state mutation. Limit incoming report to MaxPayloads and queued repairs to MaxPayloads; reject queue growth beyond limit.
- [ ] Test caller mutation of metadata, source payload, and action payload cannot alter future repairs.

## Task A3: receiver transitions

Track the next contiguous full-set boundary. Earlier-set progress recovers any subsequent missing set on its next receive deadline; it does not immediately replay gap reports based on a previously observed later set. Recovery targets the earliest incomplete set that is known to be due, not every block in the announced body immediately. First received block may be the last. Progress refreshes the receive deadline and resets missing retry count; duplicates do neither. An immediate gap report counts as the first retry attempt and sets its next exponential deadline; zero configured retries suppress immediate reports. Only the latest newly completed contiguous boundary emits Continue, avoiding bursts of obsolete acknowledgments.

| State/event | Action/state change |
| --- | --- |
| Empty + valid block | Store copied fragment; start receive timer |
| Incomplete + new block | Store; reset recovery counter; possibly emit a missing report when this packet belongs to a later set |
| Incomplete + completes contiguous full set | One SendContinue for the latest newly completed contiguous full-set boundary |
| Incomplete + duplicate | Q1 Duplicate action; Q2 none; no timer refresh |
| Incomplete + timer | Request bounded missing list from earliest due set; increment retry count; schedule exponential retry |
| Missing retry limit reached | Complete(ErrRetriesExhausted), Release; discard storage |
| Complete body | Deliver once; Q1 retains duplicate recognition, Q2 Release |
| Delivered Q1 + duplicate | Duplicate only; never Deliver again |
| Lifetime/Cancel | Release once; Complete(error) only if body was not delivered |
| Invalid metadata/block | Error without state or timer changes |

- [ ] Test final-first assembly, duplicate completion, missing first/middle/last, lost Continue (timeout requests next due set), and late-set gap detection.
- [ ] Test retry count/backoff with exact fake timestamps; duplicates never postpone expiry; progress resets retry budget.
- [ ] Test cancellation and lifetime clear Body and return no further actions.
- [ ] Test queued timeout reporting stays within a fixed set and MaxPayloads.
- [ ] Run receiver tests red, implement, then green; assemble only after Body.Complete.

## Part B: operation manager (separate task-level plan after Part A review)

Part B must implement the remaining milestone 2 requirements before milestone 3 integration:

1. Parse and validate complete wire metadata, repeated Request-Tag identity and operation options, and ETag representation changes. Reject unsupported SZX before committing offsets.
2. Own bounded transfer/byte/token/MID registries; account for action snapshots and assembled allocations. Expose packet/send-result/timer/cancel entry points and the earliest global deadline.
3. Translate normalized actions to Q1/Q2 controls, validate token ownership, handle terminal Q1-to-Q2 response transition, and retain application outcomes for duplicate uploads.
4. Apply shared peer probing-rate budgets and MTU-bounded report encoding. Support Q2 M-bit expansion without amplification.
5. Prove loss of all initial packets ends at a deadline, token collisions cannot overwrite another operation, late packets cannot resurrect released state, and every error path releases accounting.

Part A's tests cannot establish these manager properties. Keep the UDP disabled gate until the manager, adapter, and capability milestones are ready.
